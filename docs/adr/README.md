# WHYLINE architecture decision records

These records expand the twelve summaries in `TECH_PLAN.md` section 1.2. Each file has the same sections: Status, Context, Decision, Alternatives rejected, Consequences, Related.

| ADR | Title | Status | Decision |
|---|---|---|---|
| [ADR-001](ADR-001-scripted-kickoff-engine.md) | Scripted Kickoff engine is the live world | Accepted, 2026-10-21 | A deterministic, batched numpy engine with hidden tactical truth produces events and tracking for both modes; the learned policy is an optional decision model inside it. |
| [ADR-002](ADR-002-decision-only-policy.md) | Decision-only learned policy, 6-8 s horizon, hand-off to the goal-in-8-s head | Accepted, 2026-10-21 | The policy is called only at decision points, learned horizons stop at 8 s, and terminal states are valued by `GoalIn8sHead`. |
| [ADR-003](ADR-003-replay-from-cache.md) | Replay-from-cache is the demo mechanism | Accepted, 2026-10-21 | Every output for the golden match is precomputed, hashed and indexed in a manifest, then served by `CacheClient` with simulated latency; the manifest is frozen after day 7. |
| [ADR-004](ADR-004-claude-model-routing.md) | Claude model routing with Gemini as fallback and video tagger | Accepted, 2026-10-21 | Opus 5.5 for golden-match Tactician (Batch, tool results inlined by precompute) and recaps, Sonnet 5.5 for live reasoning with MCP tools, Haiku 5.5 for fast lines, Gemini 3.8 Flash as narrator fallback and optional video tagger, all called directly rather than through Foundry. |
| [ADR-005](ADR-005-agent-framework-workflows.md) | Microsoft Agent Framework graph workflows with file checkpoints locally and Cosmos in Azure | Accepted, 2026-10-21 | One `WorkflowBuilder` graph per moment, `FileCheckpointStorage` locally and for the recorded demo, `CosmosCheckpointStorage` in Azure with a file-store fallback, and human approval through `ctx.request_info()` and `@response_handler`. |
| [ADR-006](ADR-006-mcp-only-data-path.md) | The MCP server is the only data path for LLM agents | Accepted, 2026-10-21 | LLM agents read events, pitch control, counterfactuals and stats only through `whyline-mcp` tools, attached with `MCPStreamableHTTPTool`; code executors write through the worker's `Blackboard` client, the only writer. |
| [ADR-007](ADR-007-cue-sheet-boundary.md) | The Cue Sheet is the editorial product boundary | Accepted, 2026-10-21 | Everything below produces `cue.schema.json` and everything above renders it; the world-state stream is a separate feed. |
| [ADR-008](ADR-008-2d-overlay-3d-replay.md) | 2.5D canvas for live overlays; one stylised 3D scene for Sliding Doors replays | Accepted, 2026-10-21 | The live overlay is Canvas 2D with DOM lower-thirds; Sliding Doors replays use one React-Three-Fiber scene with capsule players and two cameras. |
| [ADR-009](ADR-009-azure-free-tier.md) | Azure free account hosting | Accepted, 2026-10-21 | Static Web Apps, scale-to-zero Container Apps and Cosmos DB free tier host the system; tracking runs over the `api` WebSocket and Web PubSub carries cues only; Event Hubs Basic only during judging; no GPU. |
| [ADR-010](ADR-010-english-only-no-voice.md) | English only, no voice | Accepted, 2026-10-21; amended 2026-10-26 | No Localizer agent, no TTS and no audio in cues; `cue.text` is one English headline and body. Amendment: the v9 demo video has Gemini TTS narration (intro and architecture only). |
| [ADR-011](ADR-011-spend-caps-in-code.md) | Spend caps in code | Accepted, 2026-10-21 | Every model call goes through `SpendGuard`, which prices it, appends to the ledger (Cosmos in Azure, mirrored to the committed file), and switches to degraded mode at the per-match, per-day or project-total cap; CI fails above $50. |
| [ADR-012](ADR-012-pretrained-first-one-model.md) | Pretrained models wherever one exists; one model needs a training run of its own | Accepted, 2026-10-21 | Only the on-ball decision policy needs an overnight run on the Mac GPU; the heads, chaos head and moment encoder are also trained but small; vision uses COCO-pretrained RF-DETR. |

Sources: `TECH_PLAN.md` 1.2 and the sections cited in each ADR, `FEASIBILITY_AUDIT.md` (Part A table, Parts B, C, E), `DEMO_MASTERPLAN_50USD.md` sections 1 to 3, and the files under `config/` and `schemas/`.
